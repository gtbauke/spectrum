# Profile Models Section Design Spec

**Date**: 2026-04-04
**Topic**: Profile Models Display & Interaction

## Overview

The Models section of the Profile Editor provides a library of mathematical results (EGGP equality-graphs) generated by symbolic regression jobs. Its primary purpose is to allow users to identify and reference discovered models in **Inference Scripts (IQL)**.

## User Experience

- **Visuals**: A grid of Discovery Cards within the Profile Editor, following the aesthetic of the "Datasets" and "Jobs" sections.
- **Interactivity**: Each card prominently displays the model name and the Job that generated it. A "Copy Name" button allows users to quickly paste the model identifier into an `InferenceBlock`.

## Architecture & Components

### [ProfileModelsSection](file:///home/gusta/dev/spectrum/packages/frontend/app/components/ui/notebook/sections/models/models-section.component.tsx)
- Top-level section container.
- **Props**: `models: Model[]`, `jobs: Job[]`.
- **Logic**: Maps over the `models` array and renders a `ModelItem` for each. Performs a lookup in the `jobs` array to find the parent Job Name associated with `model.generatedBy`.

### [ModelItem](file:///home/gusta/dev/spectrum/packages/frontend/app/components/ui/notebook/sections/models/model-item.component.tsx)
- Individual card for a single Model discovery.
- **Elements**: 
    - Icon: `Square3Stack3D` (representing a complex structure or graph stack).
    - Status: "Discovered" (visual badge).
    - Origin: "Generated by [Job Name]".
    - Action: Secondary button with a "Clipboard" icon to copy the `model.name`.

## Data Flow

1. `ProfileEditor` fetches the full `Profile` (which includes `models` and `jobs`).
2. `profile.models` are passed into `ProfileModelsSection`.
3. For each model, the component performs a reverse lookup:
    - Finds `job` where `job.runs` contains a run with `id === model.generatedBy`.
4. The resolved `job.name` is displayed as the model's source.

## Design Decisions

- **Why Copy Name?**: The user uses the semantic name in IQL scripts for exploration, rather than the raw UUID.
- **Why Card Layout?**: Consistently maintains the "Collection of Resources" visual language established in the notebook interface for Datasets and Jobs.
- **No Create Action**: Models are strictly the outputs of Jobs, so no "Add" or "Create" UI is needed.
