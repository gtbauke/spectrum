# Symbolic Regression Validation Service Rewrite Design

This design outlines the rewrite of the `ValidationService` expression evaluation engine and the corresponding synchronization with the `ModelInsights` frontend component. The goal is to support stable, ID-based model identification and robust matrix-based expression evaluation.

## 1. Background

The current validation pipeline uses array indices (e.g., `expr_0_predicted`) to store results in CSV format. This is brittle because the Pareto Front order can change during recalculation. Additionally, expressions generated by the `reggression` library use NumPy-style indexing (`x[:, i]` and `t[i]`) which aren't fully supported by the current evaluation context.

## 2. Proposed Changes

### 2.1 Backend: `ValidationService` Rewrite

#### Update `_calculate_predictions`
The signature will be updated to accept a list of unique `Ids`:
- **Variable `x`**: Mapped to a 2D NumPy array of shape `(N, D)`, where `D` is the number of feature columns. Only the column strictly named `"target"` will be excluded from the feature matrix.
- **Variable `t`**: Mapped to the parameter list `p_list` for each expression, enabling indexing like `t[0]`.
- **Legacy Support**: Individual `x0, x1...` and `t0, t1...` variables will be provided in the `eval_context` for fallback compatibility.
- **Result Schema**: Predictions will be stored in columns named `model_{id}`, where `{id}` is the unique identifier from the Pareto Front.

#### Update `validate()`
- Pluck the `Id` column from the `pareto_df` after verification.
- Pass the `ids` list to `_calculate_predictions`.

### 2.2 Frontend: `ModelInsights` Sync

- **Selection State**: The `selectedIndices` state (Set of numbers) will remain, but it will represent the `Id` of the model, not its array index.
- **Data Lookup**: The comparison chart series will fetch data using the key `model_{item.Id}` from the `validationData` records.
- **UI Logic**: Labels like "UNIT 0" (based on index) can be updated to use the model ID for clarity.

## 3. User Review Required

> [!IMPORTANT]
> **Strict Target Column**: The rewrite assumes that the validation dataset MUST have a column named `"target"`. If this column is missing, the validation run will now raise a `ValueError` for safety.

## 4. Open Questions

None. The user has approved the ID-based mapping and matrix indexing approach.

## 5. Verification Plan

### Automated Verification
- **Functional Check**: Run a validation job and verify the `results.csv` contains `model_{id}` columns.
- **Math Check**: verify that expressions like `t[0] * x[:, 0]` evaluate without errors.

### Manual Verification
- Open the "Validation Performance" tab in the `ModelInsights` modal.
- Verify that selecting multiple models overlays their prediction lines correctly.
