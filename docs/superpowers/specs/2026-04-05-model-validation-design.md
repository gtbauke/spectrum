# Model Validation & Property Graphics Design

**Date**: 2026-04-05
**Status**: Proposed

## 1. Goal

The goal of this feature is to provide detailed insights into the performance of symbolic regression models generated by the platform. This involves:
- Validating the **Pareto front expressions** (found during training) against a separate **validation dataset**.
- Calculating performance metrics (RMSE, MAE, R², complexity) for each expression.
- Storing the validation results efficiently in **Parquet files**.
- Visualizing the results in the frontend using **Apache ECharts**.

## 2. Architecture

### 2.1 Event-Driven Workflow

1.  **Training Complete**: The `RunCreatedHandler` finishes training and creates a `Model` entity.
2.  **Emit Event**: It emits a `RunFinishedEvent` containing `run_id`, `job_id`, and `model_id`.
3.  **Validation Process**: A new `RunFinishedHandler` (in the `workers.validation` queue) catches the event and:
    -   Loads the training `results.csv` (Pareto front).
    -   Loads the **Validation Dataset artifact** from the associated Job.
    -   Evaluates each Pareto expression on the validation inputs.
    -   Saves a Parquet file with columns: `target_y`, `expr_0_predicted`, `expr_1_predicted`, etc.
4.  **Database Update**: The `Model` entity is updated with `validation_path` and aggregated `metrics` (JSONB).

### 2.2 Data Storage

-   **Metadata**: Stored in PostgreSQL (`ModelORM.metrics`) for fast querying of Pareto front statistics.
-   **Bulk Data**: Predicted values for all Pareto front expressions against the large validation set are stored in `.parquet` files. This is more efficient for the frontend to download and for storage than a JSONB column.

## 3. Component Details

### 3.1 Worker: `ValidationService`

-   **Dependency**: `eggp` (for evaluation), `pandas`, `pyarrow`.
-   **Logic**:
    -   Use `Reggression(dataset=validation_path, loadFrom=model_path)` to evaluate the expressions.
    -   Since `Reggression` might be optimized for training, we'll implement a clean `evaluate(expression_string, inputs)` method or use the `IQL` query executor.
    -   **Performance**: Evaluation should be offloaded to a threadpool via `asyncio.to_thread` as it's CPU-bound.

### 3.2 Frontend: `ModelInsights`

-   **Library**: `echarts-for-react`.
-   **Charts**:
    -   **Interactive Pareto Front**: A scatter plot of Error vs. Complexity. Clicking a point selects that expression for the "Predicted vs Actual" chart.
    -   **Value vs Expected Value**: A scatter/line chart showing the validation fit. It supports zooming and multi-series selection.
    -   **Latex Rendering**: Selected expressions are rendered using `react-katex`.

## 4. Error Handling

-   **Missing Validation Artifact**: If no artifact with `role == VALIDATION` is found, the validation step is skipped or marks a warning in the `Model.metrics`.
-   **Evaluation Failures**: If an expression causes an overflow or evaluation error, it is skipped with a logged warning, and the metric is set to `null`.

## 5. Future Considerations

-   **Cross-validation**: Extending this to support multiple validation folds.
-   **Exporting Results**: Allowing users to download the Parquet file directly for external analysis in Python/R.
